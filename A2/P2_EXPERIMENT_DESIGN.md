# P2 Head 小目标检测实验设计文档

## 1. 问题背景：小目标候选 anchor 严重不足

### 1.1 根本原因

YOLO 的 TAL（Task-Aligned Assigner）标签分配机制中，anchor 点以 stride 为间距均匀分布在特征图上。标准 YOLO26n 使用三个检测头：

| 检测头 | stride | 特征图尺寸 (640×640) | anchor 点数 |
|--------|--------|---------------------|------------|
| P3 | 8 | 80×80 | 6,400 |
| P4 | 16 | 40×40 | 1,600 |
| P5 | 32 | 20×20 | 400 |
| **合计** | | | **8,400** |

一个 5×5 px 的小目标，在 stride=8 的特征图上仅覆盖约 **0.4 个 anchor 点**。即使代码将其宽高扩充到 16×16，也只能覆盖 **4 个 anchor 点**——而 TAL 默认要求选出 top-10 个正样本。候选点严重不足。

### 1.2 P0 baseline 的 assignment 数据（epoch 13）

| 指标 | 小目标 | 中目标 | 大目标 |
|------|--------|--------|--------|
| 每 GT 正样本数 (o2m) | **3.39** | 9.88 | 9.93 |
| 零正样本 GT 比例 | **11.1%** | 0.04% | 0% |

> 小目标每个 GT 平均只有 3.39 个正样本，且有 11.1% 的小目标完全没有任何正样本——这些目标在训练中直接被忽略，模型永远学不会检测它们。

---

## 2. 解决方案：P2 Head（stride=4）

### 2.1 核心思路

引入第四个检测头 P2，stride=4，提供更密集的 anchor 网格：

| 检测头 | stride | 特征图尺寸 (640×640) | anchor 点数 |
|--------|--------|---------------------|------------|
| **P2** | **4** | **160×160** | **25,600** |
| P3 | 8 | 80×80 | 6,400 |
| P4 | 16 | 40×40 | 1,600 |
| P5 | 32 | 20×20 | 400 |
| **合计** | | | **34,000** |

### 2.2 为什么大目标不能也用 stride=4

P2 的 25,600 个 anchor 点会带来两个问题：

1. **计算量暴增**：TAL 的 `select_candidates_in_gts` 需要计算每个 anchor 是否落在每个 GT 框内，复杂度 O(A × G)，anchor 数从 8,400 增加到 34,000 会让标签分配时间翻倍以上
2. **大目标过拟合风险**：大目标（如 100×100 px 的汽车）在 stride=4 下会覆盖 625 个 anchor 点，远超 top-10 的需求，模型可能学到冗余的、噪声更大的特征

因此，**P2 的 anchor 点只对面积 < 1024 px²（即 COCO 标准的小目标）的 GT 框开放**，大/中目标仍然使用 P3/P4/P5 的 anchor。

### 2.3 实现：面积门控

在 `tal.py` 的 `select_candidates_in_gts` 中增加门控逻辑：

```
如果 stride < 8（即 P2 head）：
    对于每个 GT 框：
        如果 GT 面积 >= 1024 px²（非小目标）：
            屏蔽该 GT 在 P2 anchor 上的所有候选点
```

## 5. 实验意义

### 5.1 核心贡献

本实验验证了一个关键假设：**小目标检测性能受限于 TAL 标签分配阶段的候选 anchor 点数，而非模型容量或特征表达能力**。通过引入 P2 head（stride=4）并按面积门控仅对小于 1024 px² 的目标开放，小目标的正样本覆盖率从 89% 提升到 98.4%，零正样本 GT 比例降低 86%。

### 5.2 与扩大框方案的对比

| 方案 | 小目标候选点 | 副作用 |
|------|------------|--------|
| 原版（无扩框） | ~0.4 个 | 大量小目标无候选 |
| 扩框到 16×16 | 4 个 | 框与目标本身关联性下降 |
| **P2 head（本实验）** | **7.81 个** | 仅增加计算量，不改变框的语义 |

P2 head 提供的是"真实"的细粒度 anchor，而非简单扩大框后"借用"的粗粒度 anchor，因此语义更加合理。

### 5.3 后续方向

1. **增加 P2 实验的训练 epoch**（如 50 epoch）以观察充分收敛后的效果
2. **尝试 P2 预训练权重**以加速收敛
3. **探索面积阈值的调优**（当前 1024 px² = 32×32）
4. **结合 STAL 动态 topk 调整**，进一步优化标签分配
